# `appendfs` Future Feature Backlog & TODO

## Future Enhancements & Backlog

- [x] **Log File Revision Identifiers for Compaction:** Add a revision identifier to the log file naming scheme (e.g., `000001-00.log` or `000001_r0.log`) after the generation ID. This will allow future log compaction routines to rewrite existing log generations while preserving the original generation ID and advancing the revision number.
- [x] **Multi-Write Batch Records (`OP_BATCH_WRITE`):** Batch small staged writes across multiple files into a single log record payload to minimize header overhead for high-frequency micro-writes. *(Superseded by in-memory batch staging via `live` layer and `WriteArena`, flush-time contiguous extent coalescing, overwrite elimination, and single `FlushCommit` batch trailers; cross-file payload packing would degrade per-file caching and extent indexing).*
- [x] **Coalesce Adjacent Writes:** When flushing a batch, merge adjacent (contiguous or overlapping) staged writes to the same file into a single write record instead of one record per write, reducing per-record header/checksum overhead for high-frequency sequential writers. Apply the same coalescing when exporting a `.summary` file.
- [x] **Elide Partially-Overwritten Bytes Within a Flush Batch:** Synthesizing writes directly from `ExtentMap` at flush time ensures that superseded/overwritten bytes within a flush batch are eliminated and never written to disk, emitting only the surviving merged contiguous extents.
- [x] **Extended Attributes (`xattrs`):** Support POSIX extended attributes (`setxattr`, `getxattr`, `listxattr`, `removexattr`) for desktop metadata (e.g. macOS Finder tags, custom user attributes).
- [x] **File Locking (`flock` / `fcntl`):** Support advisory/mandatory FUSE record locking for application concurrency (e.g. SQLite, Git, office applications) with non-busy waiter queue thread parking.
- [x] **Summary Catalog Exporter CLI:** Add a CLI command/utility (`appendfs catalog <summary_file>`) to parse and print a human-readable file manifest directly from a `.summary` snapshot file without mounting FUSE. *(Implemented via `appendfs dump <summary_file> -v`, which parses and prints the full directory/file tree, resolved paths, metadata attributes, and extent mappings directly from `.summary` files without mounting).*
- [ ] **Live Log Streaming:** Optional real-time log streaming transport protocol for continuous remote replication to a secondary server/cluster.
- [x] **Native Encryption & KDF:** Authenticated AEAD encryption (ChaCha20-Poly1305) under a key file (optionally Argon2id passphrase-protected), and key check values.
- [ ] **Key Rotation via Compaction:** Support re-encrypting older log generations with a rotated volume key during log compaction.
- [x] **Coalesce Concurrent Remote Reads:** When multiple concurrent threads or readers request extents residing in the same remote 1 MiB block (or overlapping/adjacent ranges), coalesce in-flight remote requests (single-flight / request deduplication) so only one range request is issued over the network while concurrent readers await the shared fetch, preventing redundant network egress and duplicate cache writes.
- [x] **Parallel Execution of Multi-Extent Cold Reads:** When a `ReadPlan` contains multiple cold extents (e.g. spanning different log files or remote storage blocks), dispatch the extent fetches in parallel across worker tasks (e.g. via `join_all` / concurrent blocking tasks) rather than sequentially to maximize I/O throughput for large scattered reads.
- [x] **Store Physical Record Size in Extent Map:** Store the physical (compressed/encrypted) record size in the extent map (`ExtentState::Disk`). This allows fetching each record in a single contiguous disk read rather than a two-phase read (reading the 37-byte `RecordHeader` first to discover `payload_len`, followed by reading the payload).
- [x] **Multi-Block Cache Reads & S3 Range Fetch Batching:** Support reading multiple adjacent blocks from the on-disk block cache, and coalescing missing adjacent blocks into a single contiguous multi-megabyte HTTP Range GET request from remote storage (e.g., S3) rather than issuing separate 1 MiB requests.
- [ ] **Fast-Path Selective Inode Syncing (`fsync` / `fdatasync`):** Improve `fsync` / `fdatasync` latency by selectively syncing only the requested inode when safe, rather than flushing the entire `live` layer. To preserve crash consistency and avoid orphan inodes or split-brain directory structures, use a dual-path strategy: fast-path selective sync for pre-existing regular files in `base` with pure data/attribute mutations and an empty flush queue; fallback to a full batch flush (`flush_log`) whenever structural mutations (new files, directories, moves/renames, unlinks, or pending queue depth > 0) are involved.
- [x] **Explicit Log File Terminal Seal Records (`OpCode::Seal`):** Add an explicit terminal record (`OpCode::Seal`) written as the final record when a log generation is cleanly closed (e.g. upon reaching size/age limits during log roll, or during clean unmount). The record payload can store final generation statistics (total records/batches, last transaction ID, sealing timestamp, and roll reason: size, age, unmount, or compaction). During offline verification (`appendfs fsck`) or recovery (`recover_fs`), intermediate generations lacking a seal record can be flagged as truncated or corrupted, while the active head generation can be recognized as ending in an unclean crash vs. a clean unmount without guessing. Crashed log files remain immutable and untouched during recovery, with the lack of a seal record acting as diagnostic evidence of an abnormal termination.
- [x] **Replace libc Time Conversion with a Date Crate:** `clock.rs` converts between `SystemTime` and civil calendar fields through `libc::gmtime_r`, `libc::localtime_r`, `libc::strptime` and `libc::timegm`, because the standard library has no civil calendar at all. Adopting `chrono` (or `jiff`) would remove the remaining `unsafe` blocks from `clock.rs`, drop the `civil_parts` shim, and give `parse_timestamp` a better-specified grammar than `strptime` offers. Weigh against the dependency footprint - `chrono` pulls in `iana-time-zone` for local-time support.
- [x] **Collapse / Normalize Directory No-Op Deltas at Batch Freeze Time:** When self-canceling directory operations occur within the same flush batch (such as `mv a b; mv b a`, or `touch foo; rm foo`), the in-memory `DirectoryDelta` accumulates redundant additions and phantom tombstones (e.g. `added: ["a" -> 123], removed: ["b"]`). When preparing a batch to be flushed and written to disk, normalize directory deltas against the folded `base`: retain `added` entries only if `base` does not already map `name` to the exact same `child_ino`, and retain `removed` entries only if `name` actually existed in `base`. This elides redundant additions and phantom tombstones from log batches with zero disk I/O, writing only genuinely modified directory entries or pure timestamp attribute deltas.

- [ ] **Lazy / Paged On-Disk Base Inode Layer:** Avoid loading the entire `.summary` inode map into `FsInner::base` at mount time by keeping the lowest layer of `InodeLayerStack` on disk backed by an in-memory LRU cache (with open files and optionally directories pinned) and an in-memory `folded` delta layer for mutations flushed since the summary. Requires a summary format bump so inodes are written in independently compressed and AEAD-authenticated fixed-size blocks with a compact sparse block index `(first_ino, disk_offset, disk_len)`, plus a streaming merge-join on summary export and pre-lock / `DeferredResult` threadpool paging on cold inode misses so neither `AppendFs::inner` nor the single-threaded FUSE loop blocks on disk I/O.
